# Отчёт о выполненных проверках

Дата: 26 ноября 2026 года. Среда: Linux, Python 3.12, реальный Chromium через браузерный интерфейс. Скриншоты сняты с работающего FastAPI-приложения; это не макеты.

## Автоматические проверки

После завершения изменений выполнено `python -m pytest -q`:

**30 passed, 2 warnings in 0.88s.** Полный вывод сохранён в `pytest-output.txt`.

Проверены:

- Главная, портфолио, политика, robots, CSS и JavaScript: HTTP 200 и защитные заголовки.
- Реальная запись полей заявки в изолированную SQLite.
- Повторная отправка: одна запись, второй ответ без дублирования.
- Шесть параллельных одинаковых обращений: создаётся только одна запись.
- Ошибочные email, имя, короткое/длинное сообщение, отсутствие согласия, неизвестная услуга, лишнее поле.
- Некорректный JSON, неверный Content-Type, тело больше 16 KiB.
- Honeypot, изменённая подпись, слишком ранняя отправка, истёкший токен.
- Запрет постороннего Origin и ограничение 5 новых заявок за 600 секунд.
- SQL-инъекция сохраняется как строка, таблица остаётся доступной.
- Отсутствие публичного чтения заявок, базы, Swagger и OpenAPI.
- Ошибка SQLite возвращает 503 без внутренних подробностей.
- Все локальные ссылки ресурсов и все варианты фотографий доступны.

Два предупреждения приходят из установленных зависимостей: AnyIO использует устаревающее имя Pytest API, а Starlette предупреждает о будущем переходе тестового клиента с HTTPX на HTTPX2. Ошибок тестов нет. Не заявляется совместимость с будущими версиями зависимостей.

Также выполнен `node --check` для обоих JS-файлов, без синтаксических ошибок.

## Браузерные проверки

- Осмотр главного экрана, галереи и мобильной композиции.
- Открытие мобильного меню и переход к работам.
- Фильтр «Портреты» оставил две работы.
- Открытие dialog, переход к следующей работе и закрытие через Escape.
- Заполнение формы вымышленными данными в мобильной композиции и успешная отправка.
- Ответ формы: «Спасибо! Ваша заявка сохранена…». Запись дополнительно подтверждена прямым чтением SQLite (`browser@example.com`). Рабочая тестовая БД не включена в архив.
- Наблюдаемые ошибки консоли относятся к браузерному расширению (`chrome-extension://`), а не к JavaScript проекта. Полный длительный сбор телеметрии не проводился.

## Адаптивность

Для точной смены размера использовался временный тестовый стенд с same-origin iframe. Его ширина задаёт реальный viewport документа, поэтому media queries вычисляются для указанных размеров. Это проверка Chromium, а не эмуляция конкретных моделей телефонов. Стенд удалён из итогового проекта.

| Viewport, px | Доступная ширина, px | scrollWidth, px | Горизонтальная прокрутка |
|---|---|---|---|
| 320 | 305 | 305 | Нет |
| 375 | 360 | 360 | Нет |
| 390 | 375 | 375 | Нет |
| 768 | 753 | 753 | Нет |
| 1024 | 1009 | 1009 | Нет |
| 1440 | 1425 | 1425 | Нет |
| 1920 | 1905 | 1905 | Нет |

Разница 15 px — обычная вертикальная полоса прокрутки Chromium. Исходные измерения: `viewport-results.json`. На всех ширинах измерено переполнение; визуально дополнительно осмотрены 320, 390, 768, 1024, 1920 px и обычный desktop viewport. Проверка каждого пикселя каждого блока на всех размерах не заявляется.

## Что не проверено

- Реальные Windows, iOS/Android, Safari и Firefox.
- Реальные сенсорные свайпы: обработчик добавлен, аппаратное тестирование не выполнено.
- Runtime-переключение prefers-reduced-motion: реализация проверена по коду, системная настройка браузера не переключалась.
- Lighthouse/Core Web Vitals, медленные мобильные сети, длительная нагрузка и независимый аудит безопасности.
- Screen reader и полный аудит WCAG. Базовые семантика, подписи, focus/ARIA реализованы; это не сертификат соответствия.
- Хостинг, HTTPS, домен и почтовые уведомления. Внешняя публикация не выполнялась.

## Производительность и ограничения

Все 14 WebP-файлов занимают 1 320 490 байт суммарно. Браузер выбирает нужный размер через srcset; фото ниже первого экрана используют lazy loading. Нет внешних JS/CDN/шрифтов. Эти факты не заменяют замеры времени загрузки на реальной сети.

SQLite рассчитана на небольшую нагрузку и постоянный диск одного сервера. Защита от спама базовая, распределённые атаки она не останавливает. Для идентификации клиента используется request.client.host; proxy нужно настроить корректно. При смене APP_SECRET старые токены и сопоставление хешей больше не действуют.
