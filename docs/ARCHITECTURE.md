# Архитектура и назначение файлов

## Как работает сайт

1. Браузер запрашивает `/`. FastAPI читает заранее загруженные данные, создаёт подписанный токен формы и передаёт их Jinja2.
2. Jinja2 формирует HTML; браузер отдельно получает CSS, JavaScript и фотографии из `static`.
3. `main.js` управляет меню, фильтрами и модальным просмотром. `animations.js` наблюдает появление блоков, не перехватывая прокрутку.
4. При отправке HTML проверяет обязательные поля. JavaScript отправляет JSON на `POST /api/inquiries`.
5. `main.py` проверяет тип/размер тела и Origin, Pydantic проверяет структуру и значения. Список допустимых услуг берётся из того же JSON, что и интерфейс.
6. `services.py` проверяет подпись, возраст токена и ловушку для ботов. Создаёт HMAC-хеши содержимого и клиента; исходный IP в БД не попадает.
7. `database.py` в одной транзакции проверяет повтор, частоту запросов и сохраняет заявку. Значения передаются через `?` — SQL-инъекция остаётся обычным текстом.
8. Браузер показывает ответ. При ошибке поля сохраняются, кнопка снова доступна. При успехе форма очищается.

## Основные функции

- `create_app(settings)` позволяет подменить настройки для изолированных тестов.
- `initialize(path)` создаёт таблицы и индексы один раз при запуске. WAL позволяет чтению не блокировать запись без необходимости.
- `connect(path)` всегда закрывает соединение; SQLite не держится глобально между запросами.
- `save_inquiry(...)` использует `BEGIN IMMEDIATE`: два одновременных одинаковых запроса не создадут две записи.
- `create_token(settings)` подписывает время и случайную часть. Ключ на клиент не передаётся.
- `token_age(...)` возвращает возраст только для корректной подписи.
- `submit(...)` отделяет бизнес-правила от HTTP.
- `showPhoto(index)` циклически меняет текущую фотографию и подпись.
- `closeMenu(...)` согласованно обновляет видимость и ARIA-состояние.
- `SITE_URL` валидируется при запуске; используется для canonical, OG, sitemap и разрешённого публичного Origin. Forwarded-заголовки не читаются приложением для проверки Origin.

`configureMotion()` учитывает системное предпочтение reduced motion даже при его изменении.

## Библиотеки

| Библиотека | Почему используется |
|---|---|
| FastAPI | Маршрутизация и HTTP API |
| Uvicorn | ASGI-сервер, принимает HTTP-запросы |
| Jinja2 | HTML-шаблоны, наследование, макросы и экранирование текста |
| Pydantic | Проверка и нормализация входных данных |
| email-validator | Проверка синтаксиса email для `EmailStr`, без отправки писем |
| sqlite3 (стандартная) | Локальная база без отдельного сервера |
| hmac/hashlib/secrets/time (стандартные) | Подпись, случайность и проверка возраста токена |
| Pytest | Автоматическое тестирование |
| HTTPX | HTTP-клиент для FastAPI TestClient |
| Starlette / AnyIO (транзитивные) | Основа HTTP и перенос блокирующей SQLite-операции в рабочий поток |

GSAP не добавлен: нужные эффекты реализуются средствами браузера. Нет React, Vue, сборщика и ORM. SQLite с параметризованными запросами проще для небольшого проекта и легко читается при базовом знании SQL.

## Практика для самостоятельного разбора

Теория: HTTP-маршрут принимает данные, схема проверяет, сервис решает, репозиторий сохраняет.
Пример: проследите `service` от JSON-каталога до `<select>`, `Inquiry` и таблицы.
Практика: добавьте услугу `family` в `content.json`, перезапустите приложение, отправьте тестовую заявку.
Проверка: запустите pytest и локальный просмотр заявок.
Разбор: если API возвращает 422, проверьте точное совпадение `id`, email, длину сообщения и согласие. Если 403 — обновите форму после перезапуска сервера. Если 400 — подождите две секунды и оставьте скрытое поле пустым.
